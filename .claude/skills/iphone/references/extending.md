# Как добавить телефону возможность

Приложение на телефоне — папка `ios/` этого репозитория, поэтому «нельзя» обычно значит «ещё не написано». Правила репозитория — в `CLAUDE.md` (раздел iOS); здесь только то, что касается доступа с компьютера.

## Где код

| Что | Файл |
|---|---|
| Сервер файлов, `_touch`, `_install`, вход в `_remote` (разбор запроса — `DAVHandler.handle`) | `ios/LiteBro/Phone/FileShare.swift` |
| Команды страницы `_remote/<имя>`: адрес, JavaScript, пробная вкладка | `ios/LiteBro/Phone/Remote.swift` |
| События касаний и кнопок (HID), палец внутри приложения, нажатие контрола, ввод текста | `ios/Shared/Touch.swift` |
| Сервер экрана: страница, `frame`, поток, `touch` | `ios/Screen/SampleHandler.swift` |
| Разрешение показа и «Управление касаниями» (общие для приложения и расширения) | `ios/Shared/ScreenShare.swift` |
| HTTP-сервер обоих | `ios/Shared/MiniHTTP.swift` |
| Лист «Доступ с ПК» | `ios/LiteBro/Views/PhoneAccessView.swift` |
| Права: `LiteBro.tipa`, `LiteBro-Browser.tipa`, расширение экрана | `ios/TrollStore.entitlements`, `ios/Browser.entitlements`, `ios/Screen.entitlements` |
| Сборка и подпись | `.github/workflows/ios.yml`, `ios/project.yml` |

## Как добавлять

- Новая команда приложению — ещё один `case` в `Remote.run` (`_remote/<имя>`, JSON туда и обратно): помощник доносит её как есть (`iphone remote <имя> ключ=значение`), так что новая команда работает и без правки помощника. Отдельная команда помощника нужна, только когда её вывод стоит разобрать.
- Новый путь сервера файлов — `/<секрет>/_имя` рядом с `_touch` в `DAVHandler.handle`. Имена с подчёркиванием не пересекаются с файлами.
- Всё, что действует на телефоне (нажимает, ставит, меняет), — только при `ScreenShare.control`; всё, что показывает экран, — только пока жив `ScreenShare.token`. Без секрета и без Face ID не должно работать ничего: это единственная защита в домашней сети.
- Запрос приходит не в главном потоке: работа с окнами и `WKWebView` — через `DispatchQueue.main`.
- У расширения экрана мало памяти (около 50 МБ) и своя песочница: тяжёлое и привилегированное делай в приложении.
- Меняешь ответ сервера — в том же PR меняй макет `evals/mock_phone.py`, оба помощника и `references/protocol.md`. Тесты: `python evals/selftest.py py` здесь; `powershell` и `pwsh` гоняет Actions на Windows (`.github/workflows/skill.yml`). Оба помощника обязаны проходить один и тот же набор.

## Цикл до телефона

1. Правка в ветке, PR. Собрать iOS можно только на macOS: это делает Actions («iOS») у каждого PR, меняющего `ios/`. Ошибки компиляции — в журнале запуска.
2. После слияния в `main` сборка лежит в выпуске `ios`, и телефон ставит её сам: `iphone install`. Это всегда `LiteBro.tipa` (весь телефон); поверх `LiteBro-Browser.tipa` — только с `--whole-phone` и с согласия пользователя. TrollStore ставит поверх, данные остаются. LiteBro закрывается; человек открывает его и доступ заново, ты делаешь `connect`.
3. Сборка PR (до слияния) — артефакт `LiteBro-iOS` запуска (`.tipa` внутри, хранится 14 дней). На компьютере пользователя: `gh run download <номер запуска> -n LiteBro-iOS`, если есть `gh` со входом; иначе попроси пользователя скачать с вкладки Actions. Затем `iphone install ./LiteBro.tipa`: файл ложится в папку LiteBro на телефоне, и человек ставит его сам («Файлы» → «На iPhone» → LiteBro → файл → «Поделиться» → TrollStore → Install). По запросу с компьютера телефон ставит только выпуск.
4. `iphone status`: в строке `app` — коммит сборки (`build abc1234`). Совпал — проверяй саму возможность.

## Проверка на устройстве

- Облачная сессия телефон не видит. То, что проверено только сборкой, так и называй в PR и в `CLAUDE.md` («не проверено на устройстве»), а проверку отдай сессии на компьютере или пользователю — списком конкретных шагов.
- Приложение упало или не запустилось: `iphone log --launch` (шаги запуска с памятью, стек падения), рядом `crash.txt`; системные отчёты — `Library/Logs/CrashReporter/LiteBro-*.ips`.
- Расширение экрана — отдельный процесс, в журнал приложения не пишет. Его состояние видно в листе «Доступ с ПК» (строка под адресом экрана) и по ответам на порту 8081.
- Нашёл на телефоне то, чего нет в этом скилле (что работает, что нет, какая настройка нужна), — допиши в скилл в том же PR: следующей сессии не придётся выяснять заново.
