# Оба сервера телефона по запросам

Для сессии без помощника (`curl`, браузерный инструмент) и для того, кто чинит `scripts/iphone.*`. Источник правды — код: `ios/LiteBro/Phone/FileShare.swift`, `ios/LiteBro/Phone/Remote.swift`, `ios/Screen/SampleHandler.swift`, `ios/Shared/Touch.swift`, `ios/Shared/MiniHTTP.swift`. Макет для тестов — `evals/mock_phone.py`: меняется сервер — меняется и он.

Содержание: [общее](#общее) · [файлы](#сервер-файлов-приложение) · [команды страницы](#команды-страницы-_remote) · [текст, кнопки и пальцы](#текст-кнопки-и-пальцы-_touch) · [установка](#установка-сборки-_install) · [экран](#сервер-экрана-расширение) · [рецепты curl](#рецепты-curl) · [рецепты для браузера](#рецепты-для-браузерного-инструмента)

## Общее

- Простой HTTP/1.1 без шифрования, только в сети Wi-Fi. Первый кусок пути — секрет; неверный секрет — `404` на всё.
- Соединение обслуживает запросы по одному, keep-alive есть. Тело запроса — с `Content-Length` или chunked.
- Через системный прокси к телефону ходить нельзя: в .NET `Proxy = $null`, в `curl` — `--noproxy "*"`.
- Тайм-аут на адресе файлов чаще всего значит, что LiteBro не на экране: iOS заморозила приложение, порт остаётся открытым, соединение принимается, ответа нет. Реже — телефон спит или в другой сети. Отказ в соединении (connection refused) — сервера нет: доступ закрыт, время вышло, приложение закрыто или обновлено, показ экрана не идёт.
- Не пользуйся `HEAD`: на `_touch` и на странице экрана телефон шлёт тело и на `HEAD`, и следующий ответ в том же соединении ломается.
- Заголовков `Date` и `Server` нет.
- Имена файлов приходят так, как их хранит iOS: буквы вроде «й» и «ё» разложены на букву и знак (NFD). Путь находится в любой форме, но сравнивать имена и искать по ним надо после приведения к обычной (NFC). Помощник это делает сам.
- Всё, что действует на телефоне (`_remote`, `_touch`, `_install`), работает только при включённом «Управлении касаниями» и пока не вышло время показа экрана; иначе `403`.

## Сервер файлов (приложение)

`http://<телефон>:<порт>/<секрет>/…`, порт 8080, а если он занят — первый свободный из 8082–8089. Корень: `/var/mobile` в `LiteBro.tipa`, папка `Documents` приложения в `LiteBro-Browser.tipa`. Работает, пока LiteBro на экране.

Пути кодируются по частям (`%20`, UTF-8). `.` и `..` в пути — `404`. Символьная ссылка, ведущая из корня наружу, — `404`; ссылка внутри корня показывается как то, на что она ведёт (на сборках до этого скилла — как файл длиной в несколько десятков байт, и скачивалась обрезанной).

| Запрос | Ответ |
|---|---|
| `OPTIONS` любой путь | `200`, заголовок `DAV: 1, 2` — признак, что это адрес файлов |
| `PROPFIND путь`, `Depth: 0` или `1` | `207`, XML WebDAV: сам объект, затем содержимое папки. Поля: `href`, `displayname`, `resourcetype` (`collection` у папки), `getcontentlength`, `getlastmodified` (GMT), `creationdate`. Нет объекта — `404` |
| `GET файл` | `200` с телом; с `Range: bytes=a-b`, `a-` или `-n` — `206` и `Content-Range`. За пределами — `416`. Всегда `X-Content-Type-Options: nosniff`; у HTML, XML и SVG ещё `Content-Security-Policy: sandbox`: файл телефона, открытый в браузере по этому адресу, показывается, но его скрипты не работают (иначе сохранённая страница действовала бы с секретом адреса) |
| `GET папка/` | `200`, страница HTML со списком (для человека); без косой черты — `301`. У страницы строгая политика содержимого (`connect-src 'self'`, без `unsafe-eval`): скрипт с неё достаёт только этот же адрес |
| `PUT файл` | `201` создан, `204` заменён. Нет папки, куда класть, — `409`. Пишется во временный файл рядом и переименовывается; оборванная загрузка цель не трогает. **Всегда называй файл, а не папку**: `PUT` по имени существующей папки новая сборка отклоняет (`405`), а прежние могли заменить папку этим файлом вместе со всем содержимым |
| `MKCOL папка` | `201`; уже есть — `405`; нет родителя — `409` |
| `DELETE путь` | `204`; папка удаляется со всем содержимым; корень — `403`; нет — `404` |
| другой метод | `405` |
| `MOVE` / `COPY путь`, `Destination: /<секрет>/новый/путь`, `Overwrite: T` или `F` | `201` или `204` (заменил); цель есть и `Overwrite: F` — `412`; ошибка файловой системы — `409`; нет `Destination` — `400` |
| `PROPPATCH` | `207`, ничего не меняет (так помощник узнаёт, что запись разрешена) |
| `LOCK` / `UNLOCK` | выдаётся любой замок: это для Проводника Windows |
| любая запись при «Только чтение» | `403` |

## Команды страницы: `_remote`

`POST /<секрет файлов>/_remote/<имя>` с JSON-объектом, ответ — JSON. Без пальцев: приложение само делает то, о чём просят. Есть в сборках начиная с 2026-11-27 (на более старых — `405`). Неизвестное имя — `404` и `{"error":"unknown command"}`; нет нужного поля — `400` и `{"error":"<поле>"}`.

| Имя | Тело | Ответ |
|---|---|---|
| `state` | `{}` | `{"url","title","loading","tabs","page"}` текущей вкладки; `page: false` и пустой `url` — вкладка показывает плитки |
| `open` | `{"url":"https://…","newTab":false}` | открывает адрес в текущей вкладке или в новой; отвечает как `state` (обычно ещё `loading: true`). Адрес — как его читает iOS: со схемой, без пробелов и не-ASCII (кодируй в `%XX`), иначе `400` |
| `js` | `{"code":"return document.title","timeout":20}` | код — тело async-функции в мире страницы, CSP страницы не мешает. `{"result":…}` — то, что вернул `return` (что не ложится в JSON — текстом); `{"error":"…"}` — исключение. `409` — во вкладке нет страницы; `504` — не завершился за `timeout` секунд |
| `click` | `{"x":0.87,"y":0.93}` (доли окна) | находит контрол UIKit под точкой и вызывает его действия: `{"hit":"<вид под точкой>","control":"UIButton"}`. Переключатель переключается. `"control":null` — контрола нет (строки SwiftUI, содержимое страницы), ничего не нажато |
| `closeOthers` | `{}` | закрывает все вкладки, кроме текущей; отвечает как `state` |
| `features` | `{}` | выключатели WebKit по именам: `{"имя":true,…}` |
| `probe` | `{"url":"…","parts":["agent"],"features":{"имя":false}}` | пробная вкладка: веб-вид WebKit по умолчанию плюс названные части LiteBro (`controller`, `transparent`, `agent`, `media`, `fraud`, `gestures`) и выключатели. Отвечает как `state` плюс `parts` и `features`. В режиме «Только localhost» — `409` |

## Текст, кнопки и пальцы: `_touch`

`/<секрет файлов>/_touch`.

- `GET` → `200`, JSON: какие функции нашлись на телефоне, например `{"available":true,"simple":true,"withType":true,"bks":true,"recipes":["trollvnc"]}`.
- `POST` с JSON-объектом → `204` (в том числе на непонятный объект: он просто ничего не делает). Дошло ли действие, сервер не знает.
- `POST` пальца с `"inApp": true` → `200` и JSON о том, что нашлось: `{"window":true,"key":true,"context":123,"enqueue":true,"x":117.0,"y":783.4,"hit":"UITextField"}` (`x`, `y` — точки окна, `hit` — вид под пальцем) или `{"error":"…"}`. Это не значит, что нажатие случилось.
- `POST` с телом, которое не читается как JSON-объект (оборванный текст, половина эмодзи), → `200` и отчёт как на `GET` (в нём есть `available`): ничего не сделано.
- `index` и `identity` — целые от 0 до 4294967295. На сборках до той, где появился этот скилл, другое число роняло LiteBro.

| Тело | Что делает |
|---|---|
| `{"type":"текст"}` | вставляет текст туда, где в LiteBro курсор (поле LiteBro или поле страницы); `"\b"` стирает один символ, `"\n"` — ввод. Работает |
| `{"button":"home"}`, `{"button":"side"}` | кнопка «Домой» или боковая, по всей системе. Работает; LiteBro уходит с экрана — сервер замирает |
| `{"t":"down","x":0.5,"y":0.5,"inApp":true}` затем `{"t":"up",…}` | палец внутри LiteBro: `x`, `y` — доли окна 0…1. На телефоне 2026-11-27 событие ставилось в очередь, но нажатия не было; см. [system-touch.md](system-touch.md) |
| `{"t":"move","x":…,"y":…,"inApp":true}` между `down` и `up` | движение пальца (прокрутка, перетаскивание) |
| `{"t":"down","x":…,"y":…}` без `inApp` | палец по всей системе (событие HID). На iOS 16.2 этого телефона не проходило |

Необязательные ключи пальца, для подбора рабочего варианта без пересборки: `recipe` (`"trollvnc"` — собрать касание как открытый сервер VNC для TrollStore; остальные ключи меняют рецепт), `client` (`plain`, `simple`, `admin`), `sender` (шестнадцатеричная строка), `masks` (`plain`, `webkit`), `bks` (bool), `points` (bool: точки вместо 0…1), `parentXY` (bool), `index`, `identity` (целые), `builtIn` (bool), `pressure`, `twist`, `radius` (числа). Полный список — `Touch.Options` в `Touch.swift`.

Касание — это `down`, пауза около 70 мс, `up` в той же точке. Долгое нажатие — пауза 0,8 с. Прокрутка — `down`, десяток `move` за 0,3 с, `up`.

## Установка сборки: `_install`

`POST /<секрет файлов>/_install` с `{"url":"https://github.com/ronanime-arch/LiteBro/releases/download/ios/LiteBro-PC-install.tipa"}` → `202`: LiteBro открывает команду TrollStore, тот сам скачивает сборку и ставит поверх. Принимается **только этот адрес**, буква в букву (выпуск `ios`: основная сборка под этим именем); любой другой — `403`, как и запрос без «Управления касаниями». `409` и текст — команду `apple-magnifier://` открыл бы не TrollStore, а системная «Лупа»: в настройках TrollStore выключена схема URL.

Другую сборку (из PR) телефон по запросу не ставит: положи файл на телефон (`PUT` в папку `Documents` приложения LiteBro, она видна в «Файлах» как «На iPhone → LiteBro»), человек открывает его → «Поделиться» → TrollStore → Install.

## Сервер экрана (расширение)

`http://<телефон>:8081/<секрет экрана>/…`. Работает, пока идёт показ; в любом приложении и на домашнем экране.

| Запрос | Ответ |
|---|---|
| `GET /<секрет>/` | страница для человека: картинка-поток |
| `GET /<секрет>/frame` | `200`, `image/jpeg`: экран как он есть сейчас. Заголовки `X-Frame` (номер картинки, растёт с каждым изменением экрана) и `X-Frame-Age` (сколько миллисекунд экран не менялся). `503` — картинки ещё не было. **Есть в сборках, начиная с той, где появился этот скилл; в старых — `404`** |
| `GET /<секрет>/frame?after=N` | `204` (с `X-Frame`), если новее картинки `N` ничего нет; иначе как выше. Дешёвый способ ждать изменения экрана |
| `GET /<секрет>/stream` | `multipart/x-mixed-replace; boundary=litebroframe`: части `Content-Type: image/jpeg` с `Content-Length` |
| `POST /<секрет>/touch` | то же тело, что у `_touch`, но из расширения: его песочница не пускает к системе событий, на телефоне не работало. `204`/`403` |

Картинка — JPEG до 1280 px по длинной стороне, повёрнута так, как человек видит экран.

Как телефон делает картинки — от этого зависит, чему можно верить:

- iOS отдаёт расширению кадр, только когда экран меняется. На неподвижном экране кадров нет.
- **Сборки с `…/frame`**: расширение всегда держит последний кадр, поэтому `frame` — это экран сейчас, а поток начинается с текущего экрана и не обрывается.
- **Старые сборки**: кадр кодируется, только пока кто-то смотрит поток, и не чаще раза в 0,12 с. Новый зритель первым получает картинку, сохранённую при прошлом просмотре, — она может быть старее экрана. Последний кадр быстрой анимации может потеряться. Через 10 с без изменений поток закрывается. Поэтому помощник на таких сборках сначала открывает поток, потом делает действие и верит только картинкам, пришедшим после него (`observe` в `iphone.py`).

## Рецепты curl

`F` — адрес файлов, `S` — адрес экрана, оба с косой чертой в конце. В Git Bash и на macOS/Linux:

```bash
curl -s --noproxy "*" -X PROPFIND -H "Depth: 1" "${F}Media/DCIM/"          # список (XML)
curl -s --noproxy "*" -o IMG_0001.HEIC "${F}Media/DCIM/100APPLE/IMG_0001.HEIC"
curl -s --noproxy "*" -r -4000 "${F}Media/LiteBro-Debug/log.txt"           # хвост журнала
curl -s --noproxy "*" -T ./file.pdf "${F}Media/Downloads/file.pdf"         # загрузить
curl -s --noproxy "*" -X MKCOL "${F}Media/Downloads/New"
curl -s --noproxy "*" -X MOVE -H "Destination: /СЕКРЕТ/Media/Downloads/New/file.pdf" -H "Overwrite: F" "${F}Media/Downloads/file.pdf"
curl -s --noproxy "*" -X DELETE "${F}Media/Downloads/New/file.pdf"

curl -s --noproxy "*" -o shot.jpg "${S}frame"                              # снимок экрана
curl -s --noproxy "*" -X POST -d '{}' "${F}_remote/state"                  # что открыто в LiteBro
curl -s --noproxy "*" -X POST -d '{"url":"https://example.org"}' "${F}_remote/open"
curl -s --noproxy "*" -X POST -d '{"code":"return document.title"}' "${F}_remote/js"
curl -s --noproxy "*" -X POST -d '{"type":"example.com"}' "${F}_touch"     # текст в поле с фокусом
```

В Windows PowerShell вызывай `curl.exe` (не `curl`: это псевдоним другой команды), а JSON с кавычками клади в файл и передавай `-d "@body.json"`: кавычки в аргументах PowerShell 5.1 теряет.

На старой сборке без `frame` снимок — первый JPEG из потока, и он может быть старым:

```bash
curl -s --noproxy "*" --max-time 3 "${S}stream" -o stream.bin
python3 -c "d=open('stream.bin','rb').read(); a=d.rfind(b'\xff\xd8\xff'); b=d.find(b'\xff\xd9',a); open('shot.jpg','wb').write(d[a:b+2])"
```

## Рецепты для браузерного инструмента

Открой адрес файлов (страницу со списком) и выполняй на ней JavaScript: запросы к тому же адресу разрешены.

```js
// Список папки
const xml = await (await fetch("Media/Downloads/", { method: "PROPFIND", headers: { Depth: "1" } })).text();
[...new DOMParser().parseFromString(xml, "application/xml").getElementsByTagNameNS("DAV:", "href")].map(h => decodeURIComponent(h.textContent));

// Текстовый файл
await (await fetch("Media/LiteBro-Debug/log.txt", { headers: { Range: "bytes=-4000" } })).text();

// Страница в LiteBro на телефоне: открыть адрес, выполнить JavaScript, ввести текст
const remote = (name, body = {}) => fetch("_remote/" + name, { method: "POST", body: JSON.stringify(body) }).then(r => r.json());
await remote("open", { url: "https://example.org" });
await remote("js", { code: "return document.title" });
await fetch("_touch", { method: "POST", body: JSON.stringify({ type: "example.com" }) });
```

Экран: открой во вкладке `…:8081/<секрет>/frame` и сними вкладку. Страница `…:8081/<секрет>/` показывает поток; её собственные нажатия мышью идут через расширение и на этом телефоне не работают.
