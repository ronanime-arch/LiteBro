# LiteBro (до 1.9.6 — LiteBrowser)

Лёгкий браузер для локальных проектов: C# WinForms на .NET Framework 4.8 (встроен в Windows) + Edge WebView2 (SDK 1.0.4191.47), DPI PerMonitorV2. Цель — меньше памяти, чем Chrome: у пользователя языковая модель (qwen) крутится на CPU, поэтому ОЗУ и CPU дороги.

## Сборка и проверка

- Собирается и запускается только на Windows: `build.ps1` → `dist\LiteBro-Setup.exe` (установщик `requireAdministrator`, ставит в Program Files, регистрирует в HKLM).
- **Облачная сессия (Linux) не может запустить браузер и увидеть окно.** Пиши код в ветку и открывай PR; собирает, ставит и проверяет пользователь у себя. Сборку под Linux можно попробовать (для net48 может понадобиться пакет `Microsoft.NETFramework.ReferenceAssemblies`), но она не заменяет проверку на Windows.
- `home.html` (стартовая страница) можно проверить в обычном браузере через локальный http-сервер с заглушкой `window.chrome.webview` (через `file://` не работает).
- Проверка на Windows кликами: SendKeys при русской раскладке шлёт «t» без Ctrl — нужен `keybd_event` с кодами клавиш.
- Установка или переустановка закрывает LiteBro (и старый LiteBrowser), а с ним **убивает программы проектов** (они в Job Object с KILL_ON_JOB_CLOSE), в том числе сессию агента dsh. Предупреждать пользователя.

## Правила

- **Версию не трогать.** Её ставит `build.ps1` при сборке: 1.9.(7 + число коммитов в main после `4f0130c`, считая слитый PR за один). Поэтому в `.csproj` номера нет, а в `app.manifest` стоит нейтральный 1.0.0.0. В описании PR версию не называть: она станет известна после слияния. Правило пользователя — только 1.9.x, не 1.10/2.0.
- Задачи можно выполнять параллельно в разных сессиях. Если PR конфликтует с main, сделай rebase на main и разреши конфликты.
- В описаниях PR и комментариях не писать «Generated with Claude Code». Co-Authored-By в коммитах можно.
- Комментарии в коде на английском, коротко; тексты интерфейса на русском, и у каждой новой русской фразы — строка в `src/Browser/en.tsv` (русский, табуляция, английский). В C# русская строка всегда внутри `L.T("…")`.

## Неочевидное

- Данные пользователя: `%LOCALAPPDATA%\LiteBro` — `settings.ini`, профиль WebView2 (cookie входа), `projects.json` (плитки), `icons\`, `logs\<id>.log` (вывод программ проектов), `ublock\` (скачанный uBlock Origin Lite, из этой папки ставится расширение).
- Регистрация: ProgId `LiteBroURL`, `Clients\StartMenuInternet\LiteBro`, AppUserModelId `ronanime-arch.LiteBro`, программа в `Program Files\LiteBro`, издатель ronanime-arch (всё в `Associations.cs`). Сменишь ProgId — Windows забудет выбор, и пользователю придётся заново жать «Приложения по умолчанию». Назначить браузер программно Windows не даёт: не обходить UCPD, не автоматизировать окно Параметров.
- Маршрутизация (`Router.cs`): локальные адреса (loopback, `*.localhost`, hosts) открываются в LiteBro, остальные сразу уходят в основной браузер (обработчик `.html`, обычно Chrome) без окна LiteBro. Браузеры на Chromium (Chrome, Edge, Brave, Яндекс…) запускаются с `--no-default-browser-check` (`Router.NoDefaultCheck`): http/https у LiteBro, поэтому иначе Chrome при каждом запуске просит сделать его браузером по умолчанию.
- Один процесс: мьютекс + named pipe. Повторный запуск с адресом передаёт его работающему экземпляру; вкладка на том же сайте переиспользуется.
- Стартовая страница `https://start.litebro/` отдаётся из ресурса через `WebResourceRequested`. Web messages слушаются **только** от неё (`Home.Is(e.Source)`), потому что они запускают программы. Всё, кроме самих документов (`/log/<id>/text`, `/net/log`, значки, файлы терминала), отдаётся только вкладке, которая сама на start.litebro, остальным — 403: с выключенным CORS любой сайт иначе прочитал бы вывод консолей.
- Защита страниц браузера (проверка 2026-09-29): каждое web message принимается только от своей страницы (`BrowserForm.Senders` по `PageOf`: плитки, консоль, /net, /dev, /storage, /term; `ready` — от любой). Документом с чужой вкладки открываются только сами страницы, их данные (`/log/<id>/text`, `/net/log`, значки) — только страницам start.litebro; у всех ответов `Home.Isolation` (CORP same-origin; COOP убран: после перезапуска движка страница с ним теряла связь с браузером — без плиток и переключателей); страницы получают состояние и по `NavigationCompleted`, стартовая повторяет `ready`, пока ничего не пришло; окно на start.litebro, открытое сайтом, становится обычной вкладкой без opener. Журнал в режиме «только localhost» и для заблокированных запросов не делает своих DNS-запросов (утечка через имя хоста); стеки от страниц ограничены (`MaxStacks`, `MaxStack`); CSV экранирует формулы. Значок плитки (`Favicons`) не качается с запрещённых режимом адресов, cookies — только своему хосту. В режиме «только localhost» `--force-webrtc-ip-handling-policy=disable_non_proxied_udp`. Напечатанные программой адреса — только локальные, первые 20 и только с `OpenPrintedUrl`. Канал single instance — ACL только текущего пользователя.
- Вкладки (1.9.5, `Tabs.cs`, `BrowserForm.cs`): у каждой свой `CoreWebView2Controller` в общем окружении. Фоновая вкладка: `IsVisible=false`, память Low, через 5 с чистка скрытых рендереров (`App.TrimHiddenTabs`); затем `TrySuspendAsync` (`SuspendAfter`, 1 мин по умолчанию, настраивается на /dev), затем выгрузка (`UnloadAfter`, 5 мин), только если приостановка удалась; таймер обхода — 15 с. Не замораживаются вкладки со звуком и на сайте проекта с работающей программой (dsh держит живое соединение). Выгруженная вкладка загружается по клику обычным `Navigate` и никогда не запускает программу проекта.
- Порядок плиток (1.9.6): перетаскивание на стартовой странице на pointer-событиях (не HTML5 drag and drop), страница шлёт `{type: "order", ids}`, `ProjectStore.Reorder` сохраняет. Пока плитку тащат, пришедшее от браузера состояние ждёт отпускания; одинаковое состояние страница не перерисовывает.
- Ссылки проекта (задача 7): `Project.Links` (имя + адрес, до 20). На плитке значок-счётчик открывает меню: сам проект, его ссылки, «Открыть всё» (проект в этой вкладке, ссылки — в фоновых вкладках). Страница шлёт `open` с `link` (браузер принимает только ссылку этого проекта) или `openAll`. Каждая вкладка ждёт свой адрес программы (`Launcher.StartAndWaitAsync(url)`); адрес, напечатанный программой (токен), подставляется только вместо главного. Сайты ссылок работающего проекта тоже не замораживаются (`App.IsRunningSite`).
- Плитка-терминал (задача пользователя 2026-09-30): звёздочка есть и на /term, пока там работает оболочка. PowerShell запускается с `TermPage.CommandLine` (`-NoExit -EncodedCommand`): обёртка `prompt` печатает папку (OSC 9;9), обработчик Enter в PSReadLine — принятую строку (OSC 633;E); `TermPage.Watch` читает их из вывода в `Tab.TermCwd`/`TermRunning` (xterm.js их не показывает). «Сохранить плиткой» — `Url` = `TermPage.Url`, `WorkDir` = папка, команда в `Exe` + `Args` (`Project.Command`), буквы `>_`, а если команда — `.exe` со своим значком (найден в папке или PATH), то этот значок (`Icons.FromProgram`, `SHDefExtractIcon` 128 px; у `.cmd`/`.ps1` и npm-обёрток значка нет); `OpenProject` у такой плитки (`Project.IsTerminal`) открывает терминал в папке и вводит команду (`Tab.TermCommand`). Адреса start.litebro не считаются сайтом проекта (`ProjectOf`/`OwnerOf`), значок для них не качается. Не проверено: проходят ли эти OSC через ConPTY на Windows 10.
- Избранное (`BrowserForm.ShowStar`/`ShowFavoriteMenu`): звёздочка справа в адресной строке на сайтах и файлах (из страниц браузера — только терминал), золотая, если адрес уже есть в плитке или её ссылке. Меню: «Сохранить плиткой» — новая плитка с адресом страницы как есть, у страницы проекта (`Tab.LastProject`, иначе плитка на том же сайте) берёт его программу, аргументы, папку и цвет, но не «открывать напечатанный адрес» (иначе вместо страницы откроется главный); «Добавить ссылкой в проект» — подменю плиток, свой проект первым и с галочкой; «Убрать ссылку из проекта», если страница — ссылка. Новая плитка — отдельный проект со своим `Launcher`: пока программа исходного проекта работает, адрес отвечает, и второй раз она не запускается.

Установщик (`RemoveLiteBrowser`) удаляет `Program Files\LiteBrowser`, его ключи в HKLM и ярлыки, перенацеливает закреп на панели задач (там бывают ярлыки без пути к файлу, например «Проводник»: `Shortcut.Target` → null, `IsInside` на пустом пути даёт false, а не исключение), переносит `HKCU\Software\LiteBrowser` → `Software\LiteBro` (`MoveOldState`) и, если ссылки были у LiteBrowser, снова ведёт через `LinksStep`. Браузер при первом запуске переносит `%LOCALAPPDATA%\LiteBrowser` целиком (`Settings.MoveOldData`, `Directory.Move`); не вышло — работает в старой папке и пробует в следующий раз, пустую новую папку не создаёт.

Работает только параметрами `gl`/`hl`: поиск из адресной строки, перезагрузка при выборе и `NavigationStarting` (новый поиск со страницы Google отменяется и повторяется с параметрами; назад/вперёд не трогаются). Не проверено: попадают ли в список выборы, сделанные в стандартном окне запроса движка.
- Сертификаты локальных серверов (`OnCertificateError`, `ServerCertificateErrorDetected`, только при `TrustLocalCerts`, по умолчанию выключено; `AlwaysAllow` движок помнит до своего перезапуска): у localhost, `*.localhost`, 127.0.0.0/8 и ::1 ошибка сертификата пропускается (`AlwaysAllow`, как `--allow-insecure-localhost` у Chrome); у частных сетей и остальных сайтов — страница движка.
- Сайт не отвечает (`NavigationCompleted`, `IsUnreachable`): вместо страницы движка с надписью Microsoft Edge показывается своя `Pages.Unreachable` (`NavigateToString`), адрес остаётся в `Tab.FailedUrl`, F5 и ссылка на странице пробуют снова. Только ошибки соединения (сервер выключен, имя не найдено, нет сети); ошибки сертификата остаются на странице движка, где можно продолжить.
- Консоль проекта (`ProgramLog.cs`): `https://start.litebro/log/<id>` — живой вывод программы из `logs\<id>.log` и строка ввода в stdin (`Launcher.Send`, в лог пишется `> текст`). Страница раз в 0,7 с берёт прирост `/log/<id>/text?from=<байт>` (только целые строки; файл короче смещения — программа перезапущена). Строка ввода в двух режимах: «Команда» (по умолчанию) — `Launcher.Run`: `cmd /d /s /c "chcp 65001>nul & …"` в `CommandDir` (папка проекта, иначе профиль пользователя; `cd` запоминается в браузере, потому что каждая команда — свой cmd); папку перед строкой можно исправить прямо в поле (Enter — перейти, Esc — отменить; сообщение `cd` → `Launcher.ChangeDir`, у PowerShell — `Set-Location` в самой оболочке), по одной команде, пока идёт — строки уходят ей на ввод, «Прервать команду» убивает её Job; вывод в тот же лог. «Программе» — на stdin программы. Выполнение команд со страницы — решение пользователя (2026-09-28). Консоль без проекта — PowerShell (`ProgramLog.Shell`, со стартовой страницы больше не открывается, её место занял терминал, id `shell`, `logs\shell.log`, папка пользователя): фиолетовая кнопка у левого края стартовой страницы, всегда в новой вкладке; один постоянный `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -Command -` (`Launcher.RunInShell`, решение пользователя, 2026-09-28): переменные и модули живут между командами; команда уходит на stdin как base64 UTF-8 (`. ([ScriptBlock]::Create(...)) | Out-Default`), после неё PowerShell печатает `##litebro-done##<папка>` — так браузер знает, что команда кончилась и где он. «Прервать» убивает весь процесс (переменные сбрасываются). Закрывается, когда ни одна вкладка не показывает консоль (`App.ShellMaybeUnused`). Консоль проекта открывается кнопкой `>_` на любой плитке (видна при наведении) и ссылками со страниц запуска и ошибки. Это хост стартовой страницы, поэтому web messages от неё принимаются.
- Терминал во вкладке (`Terminal.cs`, `term\`): настоящий `powershell.exe -NoLogo` в псевдоконсоли Windows (ConPTY, Windows 10 1809+), рисует xterm.js 6 (`term\xterm.js`, `addon-fit.js`, MIT, вшиты в exe) на `https://start.litebro/term`. Нужен для программ с полноэкранным вводом (claude, vim): через каналы они не интерактивны. Открывается фиолетовой кнопкой стартовой страницы (папка пользователя, в той же вкладке — `OpenTerminalHere`, Ctrl+клик — в новой; решение пользователя 2026-09-29: кнопки стартовой страницы открывают в текущей вкладке, как плитки; так же журнал и «Для разработчика» — `OpenHereOrNew`) и кнопкой «Терминал» в консоли проекта (`CommandDir`). Во всём браузере (решение пользователя 2026-09-29): клик открывает в этой вкладке, Ctrl+клик или колёсико — в новой (кнопки страниц браузера шлют `newTab`, домик панели — `MouseUp` средней кнопкой; ссылки сайтов — движок через `NewWindowRequested`). Исключение — «Хранилище сайта»: всегда своя вкладка, она работает со страницей сайта. `TermDir` сбрасывается, когда вкладка уходит с /term. Оболочку запускает только вкладка, которую браузер сам открыл как терминал (`Tab.TermDir`), по `termStart` от страницы; `termIn`/`termSize`/`termOut`/`termExit`. Вывод копится и шлётся не чаще раза за оборот UI-потока. Закрыли вкладку или ушли со страницы — Job убивает оболочку со всем, что она запустила. Терминал не замораживается; Ctrl+L, Ctrl+R, F5, Alt+D, Alt+←/→ в нём уходят оболочке. Ctrl+C с выделением копирует, Ctrl+V и правый клик вставляют.
- Сеть (`Network.cs`, `net.html`, решение пользователя 2026-09-28): режим «только localhost» (`LocalOnly` в `settings.ini`) — зелёная кнопка-переключатель у правого края стартовой страницы, зеркально PowerShell; под ней кнопка журнала `https://start.litebro/net`. Скрипт страницы `netpage.js` (`NetGuard.PageScript`, правила вместо маркера конфигурации) ставится в новые документы, пока режим или журнал включены, и сразу выполняется на открытой странице (`ExecuteScriptAsync`): повторный запуск только обновляет правила через `window.__litebroNet` и закрывает запрещённые веб-сокеты, поэтому F5 не нужен. Журнал (`NetLog`): `logs\network.log` (TSV, 5 МБ, затем `network.1.log`) и последние 2000 записей в памяти для /net; при режиме пишется всегда, без него — если `NetJournal`. Программы проектов при этом живут. Шлюз (`Gateway.cs`, решение пользователя 2026-09-28: только отсекать, без расшифровки HTTPS и без своего сертификата): в локальном режиме движок запускается с `--proxy-server=http://127.0.0.1:<свободный порт>` и `--proxy-bypass-list` (localhost, `*.localhost`, частные сети, имена из hosts и `LocalHosts`, `start.litebro`), так что локальный трафик идёт мимо, а весь остальной — через шлюз: CONNECT → туннель байтов или 403, простой HTTP — один запрос на соединение с `Connection: close`. Он ловит то, что не видит фильтр (веб-сокеты воркеров, запросы самого движка), запоминает настоящий IP и при смене правил рвёт запрещённые туннели (`Gateway.Enforce`). Включение и выключение режима меняет флаги движка и перезапускает его (`App.EngineKey`). Поэтому переключение режима (стартовая страница и /net) и CORS сначала спрашивает подтверждение (`confirm`) с предупреждением о перезапуске. Телеметрия выключена всегда: `QuietArgs` (`--disable-background-networking --disable-component-update --disable-domain-reliability --no-pings --disable-breakpad`) и `IsReputationCheckingRequired = false` (SmartScreen).

Папка — `%LOCALAPPDATA%\LiteBro\ublock`: движок пишет индекс правил (`_metadata`) в папку расширения. **Движок выбрасывает расширение, чьи файлы изменились, вместе с его настройками** (документация `AddBrowserExtensionAsync`), поэтому используемая копия при работающем движке не меняется: первая установка сразу становится папкой, а новая версия или та же, обрезанная заново (`Trim(dir, write: false)` нашёл, что менять), готовится в `ublock.new` (`StageTrimmed` копирует без `_metadata`) и встаёт на место при следующем запуске до создания окружения (`PrepareAsync`); перед этим `BackupAsync` сохраняет настройки uBOL профилей сессии в `ublock-state\<профиль>.json` (`SaveScript`: режимы сайтов, включённые списки, строгая блокировка и её исключения, режим разработчика, свои правила DNR; ещё — после каждого «Не блокировать»). Профиль, у которого расширения нет, а сохранённое есть, получает настройки обратно теми же сообщениями, что шлёт страница настроек uBOL (`RestoreScript`: `setFilteringModeDetails` сам переводит режимы в правила DNR). `Trim`: удаляет то, что достижимо только из значка на панели и всплывающего окна, которых у расширений в WebView2 нет (`Unused`: popup.js, picker/zapper/unpicker, tool-overlay, report, matched-rules; `popup.html` остаётся — его называет manifest; файл, который импортирует оставшийся модуль `js\`, не удаляется), прячет блок «Поведение» в настройках (CSS `div:has(#showBlockedCount)`, разметка нужна settings.js), кладёт пустую `litebro.html` и `litebro.js` в dashboard.html: при русском языке движка она подставляет русские названия списков на самой странице (`RussianNames` по id: английское → русское, только текстовые узлы — флаги картинками остаются; группы uBOL переводит сам), так что смена языка файлов не меняет. «Не блокировать (uBlock)» в меню «Инструменты» (id `unblock` в `Dev.Ids`, по умолчанию выключен — в `Dev.DefaultOff`, решение пользователя 2026-10-02; виден только при `AdBlock` на http/https): режим сайта uBOL принимает только от своих страниц, поэтому `AdBlock.AskAsync` открывает скрытую WebView профиля вкладки на `chrome-extension://<id>/litebro.html` и шлёт `chrome.runtime.sendMessage` (`getFilteringMode`, `setFilteringMode` с уровнем 0 или `getDefaultFilteringMode`) через `Runtime.evaluate`; галочка — из кэша, уточняется при каждом открытии меню; после смены вкладка перезагружается. Проверено в облаке на настоящем uBOL, загруженном в Chromium (Playwright): обрезка, перевод (ru и en), блок «Поведение», «Не блокировать», сохранение и восстановление с правилом `allowAllRequests`. Состояние (качается, ждёт выключения «только localhost», ошибка, нужен перезапуск) — `AdBlock.State` на /dev. `AreBrowserExtensionsEnabled` всегда true (без перезапуска движка); переключатель — `EnableAsync`. Расширение у каждого профиля своё: при первой WebView профиля за сессию (`App.CreateControllerAsync` → `AdBlock.Apply`) нет расширения с именем «uBlock Origin Lite» — `AddBrowserExtensionAsync` и восстановление; смена переключателя или окончание загрузки (`AdBlock.Changed`) применяется к профилям с WebView сразу, к остальным — при следующей.
