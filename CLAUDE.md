# LiteBro (до 1.9.6 — LiteBrowser)

Лёгкий браузер для локальных проектов: C# WinForms на .NET Framework 4.8 (встроен в Windows) + Edge WebView2 (SDK 1.0.4191.47), DPI PerMonitorV2. Цель — меньше памяти, чем Chrome: у пользователя языковая модель (qwen) крутится на CPU, поэтому ОЗУ и CPU дороги.

## Сборка и проверка

- Собирается и запускается только на Windows: `build.ps1` → `dist\LiteBro-Setup.exe` (установщик `requireAdministrator`, ставит в Program Files, регистрирует в HKLM).
- **Облачная сессия (Linux) не может запустить браузер и увидеть окно.** Пиши код в ветку и открывай PR; собирает, ставит и проверяет пользователь у себя. Сборку под Linux можно попробовать (для net48 может понадобиться пакет `Microsoft.NETFramework.ReferenceAssemblies`), но она не заменяет проверку на Windows.
- `home.html` (стартовая страница) можно проверить в обычном браузере через локальный http-сервер с заглушкой `window.chrome.webview` (через `file://` не работает).
- Проверка на Windows кликами: SendKeys при русской раскладке шлёт «t» без Ctrl — нужен `keybd_event` с кодами клавиш.
- Установка или переустановка закрывает LiteBro (и старый LiteBrowser), а с ним **убивает программы проектов** (они в Job Object с KILL_ON_JOB_CLOSE), в том числе сессию агента dsh. Предупреждать пользователя.

## Правила

- **Версию не трогать.** Её ставит `build.ps1` при сборке: 1.9.(7 + число коммитов в main после `4f0130c`, считая слитый PR за один). Поэтому в `.csproj` номера нет, а в `app.manifest` стоит нейтральный 1.0.0.0. В описании PR версию не называть: она станет известна после слияния. Правило пользователя — только 1.9.x, не 1.10/2.0.
- Задачи можно выполнять параллельно в разных сессиях. Если PR конфликтует с main, сделай rebase на main и разреши конфликты.
- В описаниях PR и комментариях не писать «Generated with Claude Code». Co-Authored-By в коммитах можно.
- Комментарии в коде на английском, коротко; тексты интерфейса на русском.

## Неочевидное

- Данные пользователя: `%LOCALAPPDATA%\LiteBro` — `settings.ini`, профиль WebView2 (cookie входа), `projects.json` (плитки), `icons\`, `logs\<id>.log` (вывод программ проектов).
- Регистрация: ProgId `LiteBroURL`, `Clients\StartMenuInternet\LiteBro`, AppUserModelId `ronanime-arch.LiteBro`, программа в `Program Files\LiteBro`, издатель ronanime-arch (всё в `Associations.cs`). Сменишь ProgId — Windows забудет выбор, и пользователю придётся заново жать «Приложения по умолчанию». Назначить браузер программно Windows не даёт: не обходить UCPD, не автоматизировать окно Параметров.
- Маршрутизация (`Router.cs`): локальные адреса (loopback, `*.localhost`, hosts) открываются в LiteBro, остальные сразу уходят в основной браузер (обработчик `.html`, обычно Chrome) без окна LiteBro.
- Один процесс: мьютекс + named pipe. Повторный запуск с адресом передаёт его работающему экземпляру; вкладка на том же сайте переиспользуется.
- Стартовая страница `https://start.litebro/` отдаётся из ресурса через `WebResourceRequested`. Web messages слушаются **только** от неё (`Home.Is(e.Source)`), потому что они запускают программы. Всё, кроме самих документов (`/log/<id>/text`, `/net/log`, значки, файлы терминала), отдаётся только вкладке, которая сама на start.litebro, остальным — 403: с выключенным CORS любой сайт иначе прочитал бы вывод консолей.
- Защита страниц браузера (проверка 2026-09-29): каждое web message принимается только от своей страницы (`BrowserForm.Senders` по `PageOf`: плитки, консоль, /net, /dev, /storage, /term; `ready` — от любой). Документом с чужой вкладки открываются только сами страницы, их данные (`/log/<id>/text`, `/net/log`, значки) — только страницам start.litebro; у всех ответов `Home.Isolation` (COOP/CORP same-origin); окно на start.litebro, открытое сайтом, становится обычной вкладкой без opener. Журнал в режиме «только localhost» и для заблокированных запросов не делает своих DNS-запросов (утечка через имя хоста); стеки от страниц ограничены (`MaxStacks`, `MaxStack`); CSV экранирует формулы. Значок плитки (`Favicons`) не качается с запрещённых режимом адресов, cookies — только своему хосту. В режиме «только localhost» `--force-webrtc-ip-handling-policy=disable_non_proxied_udp`. Напечатанные программой адреса — только локальные, первые 20 и только с `OpenPrintedUrl`. Канал single instance — ACL только текущего пользователя.
- Вкладки (1.9.5, `Tabs.cs`, `BrowserForm.cs`): у каждой свой `CoreWebView2Controller` в общем окружении. Фоновая вкладка: `IsVisible=false`, память Low, через 5 с чистка скрытых рендереров (`App.TrimHiddenTabs`); затем `TrySuspendAsync` (`SuspendAfter`, 1 мин с 1.9.6), затем выгрузка (`UnloadAfter`, 5 мин), только если приостановка удалась; таймер обхода — 15 с. Не замораживаются вкладки со звуком и на сайте проекта с работающей программой (dsh держит живое соединение). Выгруженная вкладка загружается по клику обычным `Navigate` и никогда не запускает программу проекта.
- Порядок плиток (1.9.6): перетаскивание на стартовой странице на pointer-событиях (не HTML5 drag and drop), страница шлёт `{type: "order", ids}`, `ProjectStore.Reorder` сохраняет. Пока плитку тащат, пришедшее от браузера состояние ждёт отпускания; одинаковое состояние страница не перерисовывает.
- Ссылки проекта (задача 7): `Project.Links` (имя + адрес, до 20). На плитке значок-счётчик открывает меню: сам проект, его ссылки, «Открыть всё» (проект в этой вкладке, ссылки — в фоновых вкладках). Страница шлёт `open` с `link` (браузер принимает только ссылку этого проекта) или `openAll`. Каждая вкладка ждёт свой адрес программы (`Launcher.StartAndWaitAsync(url)`); адрес, напечатанный программой (токен), подставляется только вместо главного. Сайты ссылок работающего проекта тоже не замораживаются (`App.IsRunningSite`).
- Избранное (`BrowserForm.ShowStar`/`ShowFavoriteMenu`): звёздочка справа в адресной строке на сайтах и файлах (не на страницах браузера), золотая, если адрес уже есть в плитке или её ссылке. Меню: «Сохранить плиткой» — новая плитка с адресом страницы как есть, у страницы проекта (`Tab.LastProject`, иначе плитка на том же сайте) берёт его программу, аргументы, папку и цвет, но не «открывать напечатанный адрес» (иначе вместо страницы откроется главный); «Добавить ссылкой в проект» — подменю плиток, свой проект первым и с галочкой; «Убрать ссылку из проекта», если страница — ссылка. Новая плитка — отдельный проект со своим `Launcher`: пока программа исходного проекта работает, адрес отвечает, и второй раз она не запускается.
- Переименование (1.9.7): старые имена — `Associations.OldAppName`/`OldProgId`. Установщик (`RemoveLiteBrowser`) удаляет `Program Files\LiteBrowser`, его ключи в HKLM и ярлыки, перенацеливает закреп на панели задач (там бывают ярлыки без пути к файлу, например «Проводник»: `Shortcut.Target` → null, `IsInside` на пустом пути даёт false, а не исключение), переносит `HKCU\Software\LiteBrowser` → `Software\LiteBro` (`MoveOldState`) и, если ссылки были у LiteBrowser, снова ведёт через `LinksStep`. Браузер при первом запуске переносит `%LOCALAPPDATA%\LiteBrowser` целиком (`Settings.MoveOldData`, `Directory.Move`); не вышло — работает в старой папке и пробует в следующий раз, пустую новую папку не создаёт.
- Страна поиска (`SearchCountry.cs`): кнопка справа в адресной строке видна только на `google.<tld>/search`, выбор в `settings.ini` (`SearchCountry`). Работает только параметрами `gl`/`hl`: поиск из адресной строки, перезагрузка при выборе и `NavigationStarting` (новый поиск со страницы Google отменяется и повторяется с параметрами; назад/вперёд не трогаются). Accept-Language не меняется: это перехват всех запросов.
- Две вкладки рядом (`BrowserForm.cs`): правый клик по вкладке → «Открыть рядом» / «Убрать разделение». `paneLeft`/`paneRight`, между ними перетаскиваемая граница (`divider`, 15–85 %). Вкладка в фокусе — «передняя» (`active`, панель инструментов следует за ней; переключение по `GotFocus` контроллера), вторая (`Partner`) тоже на экране: не замораживается, при сворачивании прячется. Выбор другой вкладки заменяет переднюю половину; закрытие любой половины убирает разделение. «Синхронная прокрутка» (там же в меню): в обе половины через `ExecuteScriptAsync` ставится `ScrollScript`, он шлёт строку `litebro-scroll:<доля>` (принимается от любой страницы, но только от половины разделения и двигает только вторую половину); страницы со своей прокручиваемой областью (чат dsh) — по последней прокрученной области или самой высокой.
- Сайт не отвечает (`NavigationCompleted`, `IsUnreachable`): вместо страницы движка с надписью Microsoft Edge показывается своя `Pages.Unreachable` (`NavigateToString`), адрес остаётся в `Tab.FailedUrl`, F5 и ссылка на странице пробуют снова. Только ошибки соединения (сервер выключен, имя не найдено, нет сети); ошибки сертификата остаются на странице движка, где можно продолжить.
- Консоль проекта (`ProgramLog.cs`): `https://start.litebro/log/<id>` — живой вывод программы из `logs\<id>.log` и строка ввода в stdin (`Launcher.Send`, в лог пишется `> текст`). Страница раз в 0,7 с берёт прирост `/log/<id>/text?from=<байт>` (только целые строки; файл короче смещения — программа перезапущена). Строка ввода в двух режимах: «Команда» (по умолчанию) — `Launcher.Run`: `cmd /d /s /c "chcp 65001>nul & …"` в `CommandDir` (папка проекта, иначе профиль пользователя; `cd` запоминается в браузере, потому что каждая команда — свой cmd); папку перед строкой можно исправить прямо в поле (Enter — перейти, Esc — отменить; сообщение `cd` → `Launcher.ChangeDir`, у PowerShell — `Set-Location` в самой оболочке), по одной команде, пока идёт — строки уходят ей на ввод, «Прервать команду» убивает её Job; вывод в тот же лог. «Программе» — на stdin программы. Выполнение команд со страницы — решение пользователя (2026-09-28). Консоль без проекта — PowerShell (`ProgramLog.Shell`, со стартовой страницы больше не открывается, её место занял терминал, id `shell`, `logs\shell.log`, папка пользователя): фиолетовая кнопка у левого края стартовой страницы, всегда в новой вкладке; один постоянный `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -Command -` (`Launcher.RunInShell`, решение пользователя, 2026-09-28): переменные и модули живут между командами; команда уходит на stdin как base64 UTF-8 (`. ([ScriptBlock]::Create(...)) | Out-Default`), после неё PowerShell печатает `##litebro-done##<папка>` — так браузер знает, что команда кончилась и где он. «Прервать» убивает весь процесс (переменные сбрасываются). Закрывается, когда ни одна вкладка не показывает консоль (`App.ShellMaybeUnused`). Консоль проекта открывается кнопкой `>_` на любой плитке (видна при наведении) и ссылками со страниц запуска и ошибки. Это хост стартовой страницы, поэтому web messages от неё принимаются.
- Терминал во вкладке (`Terminal.cs`, `term\`): настоящий `powershell.exe -NoLogo` в псевдоконсоли Windows (ConPTY, Windows 10 1809+), рисует xterm.js 6 (`term\xterm.js`, `addon-fit.js`, MIT, вшиты в exe) на `https://start.litebro/term`. Нужен для программ с полноэкранным вводом (claude, vim): через каналы они не интерактивны. Открывается фиолетовой кнопкой стартовой страницы (папка пользователя) и кнопкой «Терминал» в консоли проекта (`CommandDir`). Оболочку запускает только вкладка, которую браузер сам открыл как терминал (`Tab.TermDir`), по `termStart` от страницы; `termIn`/`termSize`/`termOut`/`termExit`. Вывод копится и шлётся не чаще раза за оборот UI-потока. Закрыли вкладку или ушли со страницы — Job убивает оболочку со всем, что она запустила. Терминал не замораживается; Ctrl+L, Ctrl+R, F5, Alt+D, Alt+←/→ в нём уходят оболочке. Ctrl+C с выделением копирует, Ctrl+V и правый клик вставляют.
- Сеть (`Network.cs`, `net.html`, решение пользователя 2026-09-28): режим «только localhost» (`LocalOnly` в `settings.ini`) — зелёная кнопка-переключатель у правого края стартовой страницы, зеркально PowerShell; под ней кнопка журнала `https://start.litebro/net`. Локально: loopback, `localhost`, `*.localhost`, имена из hosts и `LocalHosts`, частные сети (10/8, 172.16/12, 192.168/16, 169.254, fc00::/7, fe80). Разрешённые сайты — `AllowHosts` (`*.x.com` = x.com и поддомены), правятся на /net. Блокировка: только пока режим включён, фильтр `*` на все запросы с `SourceKinds.All` (воркеры тоже) → ответ 403 `Blocked by LiteBro` (для документа — своя страница). Скрипт страницы `netpage.js` (`NetGuard.PageScript`, правила вместо маркера конфигурации) ставится в новые документы, пока режим или журнал включены, и сразу выполняется на открытой странице (`ExecuteScriptAsync`): повторный запуск только обновляет правила через `window.__litebroNet` и закрывает запрещённые веб-сокеты, поэтому F5 не нужен. Он оборачивает fetch, XHR, sendBeacon, EventSource (EventSource и WebSocket — через `Proxy`, чтобы работали наследование классов и `instanceof`) и шлёт строку `litebro-net:` со стеком для запросов наружу (`NetLog.NoteStack`, запись журнала ждёт стек до 0,4 с по адресу); веб-сокеты `WebResourceRequested` не видит, поэтому их тоже запрещает и записывает он. На страницах `start.litebro` не работает. Журнал (`NetLog`): `logs\network.log` (TSV, 5 МБ, затем `network.1.log`) и последние 2000 записей в памяти для /net; при режиме пишется всегда, без него — если `NetJournal`. Ответы — `WebResourceResponseReceived` (подписка только пока журнал нужен), размер из Content-Length, инициатор из `Sec-Fetch-Dest`, IP — из шлюза (в локальном режиме: адрес, к которому шлюз реально подключился), иначе своим DNS-запросом с пометкой «(DNS)». Стека нет у запросов из разметки (картинки, стили, скрипты) и у воркеров. Кнопка «Быстрые команды» на /net — окно со списком всех горячих клавиш и приёмов (массив `KEYS` в `net.html`): новую клавишу в `BrowserForm.Shortcut`, `TermKeys` или на страницах добавлять и туда. Журнал: клик по названию колонки — сортировка (по возрастанию, по убыванию, снова новые сверху), стрелка ▾ рядом — фильтр-список значений со счётчиками, как автофильтр Excel (время — по минутам, размер — по диапазонам `SIZES`; поиск в списке только при длинном списке). Текстового фильтра нет (решение пользователя). Выгрузка журнала (/net, «Выгрузить JSON/CSV»): страница шлёт `netExport` с номерами записей под фильтром, браузер берёт их из памяти (`NetLog.Export`) и пишет через SaveFileDialog; CSV через `;` с BOM для Excel. «Игнорировать CORS» (`IgnoreCors`): действует только вместе с `LocalOnly` (`NetGuard.CorsOff`), это флаг `--disable-web-security` у всего движка, поэтому смена перезапускает его в том же процессе (`App.RestartEngineAsync`: все вкладки выгружаются с адресами, ждём `BrowserProcessExited`, новое окружение, видимые вкладки загружаются снова; терминалы закрываются). Программы проектов при этом живут. Шлюз (`Gateway.cs`, решение пользователя 2026-09-28: только отсекать, без расшифровки HTTPS и без своего сертификата): в локальном режиме движок запускается с `--proxy-server=http://127.0.0.1:<свободный порт>` и `--proxy-bypass-list` (localhost, `*.localhost`, частные сети, имена из hosts и `LocalHosts`, `start.litebro`), так что локальный трафик идёт мимо, а весь остальной — через шлюз: CONNECT → туннель байтов или 403, простой HTTP — один запрос на соединение с `Connection: close`. Он ловит то, что не видит фильтр (веб-сокеты воркеров, запросы самого движка), запоминает настоящий IP и при смене правил рвёт запрещённые туннели (`Gateway.Enforce`). Включение и выключение режима меняет флаги движка и перезапускает его (`App.EngineKey`). Поэтому переключение режима (стартовая страница и /net) и CORS сначала спрашивает подтверждение (`confirm`) с предупреждением о перезапуске. Телеметрия выключена всегда: `QuietArgs` (`--disable-background-networking --disable-component-update --disable-domain-reliability --no-pings --disable-breakpad`) и `IsReputationCheckingRequired = false` (SmartScreen).
- Заглушки (`Mocks.cs`, раздел «Заглушки» на /net, задача пользователя 2026-09-29): `mocks.json` рядом с `settings.ini`; метод (пусто — любой), адрес (`*` — любые символы, без `?` подходит с любыми параметрами), код, тип, тело. Вкладки ставят фильтры запросов только на адреса включённых заглушек (`Tab.MockFilters`, в `ApplyNet`), `TryMock` в `OnNetRequest` отвечает до блокировки «только localhost», с CORS-заголовками (Origin страницы + credentials) и ответом на preflight OPTIONS; причина ответа `LiteBro mock`, в журнал пишется «заглушка <код>». «Сделать заглушку» в подробностях строки журнала: для GET браузер один раз запрашивает ответ сервера сам (`HttpClient` без cookies), но не если режим этот адрес запрещает.
- Эмуляция (`Emulation.cs`, кнопка «Инструменты» с гаечным ключом справа в адресной строке, подменю «Устройство» и «Сеть», задача пользователя 2026-09-29): на вкладку, через DevTools-протокол, как режим устройства DevTools. Экран: `Emulation.setDeviceMetricsOverride` (больший, чем место под страницей, уменьшается `scale`, заново через 0,3 с после изменения размера — `fitTimer`), касания и user agent; при смене устройства страница перезагружается. Сеть: быстрая/медленная 3G (пресеты DevTools) и офлайн через `Network.emulateNetworkConditions`; `Network.enable` только пока сеть эмулируется. Состояние в `Tab.Device`/`Speed`, новый контроллер вкладки получает его в `Setup`. Кнопка зелёная, пока что-то эмулируется.
- Хранилище сайта (`SiteStorage.cs`, `storage.html`, `sitestorage.js`, пункт меню «Инструменты», задача пользователя 2026-09-29): `https://start.litebro/storage` в новой вкладке, привязан к вкладке сайта (`Tab.StorageOf`, ставит только браузер; web message `storage` принимается только от этой страницы с этой привязкой). Cookies — `CookieManager` профиля вкладки сайта (все пути, домен сайта и родительские), localStorage, sessionStorage и IndexedDB — `sitestorage.js` через `Runtime.evaluate` (`awaitPromise`) в самой странице сайта; до 300 записей на хранилище, ключ и значение IndexedDB — JSON, двоичные данные, Map, даты и длинные значения только смотреть и удалять. Вкладка сайта, пока её хранилище открыто, не замораживается.
- Снимок и JSON (задача пользователя 2026-09-29): `BrowserForm.Snapshot` — PNG в файл через SaveFileDialog (папка «Изображения»): целиком — `FullShotAsync`: `MeasureScript` меряет документ и главную прокручиваемую область, окно на один снимок делается во всю высоту через `Emulation.setDeviceMetricsOverride` (как «Capture full size screenshot» DevTools; `captureBeyondViewport` в WebView2 давал только видимое, баг пользователя 2026-09-29), затем эмуляция вкладки и прокрутка возвращаются; до 16384 px; вёрстка на 100vh (чат dsh) растёт вместе с окном и тоже снимается целиком, видимая часть — `CapturePreviewAsync`; Ctrl+Shift+S и меню «Инструменты». `jsonview.js`: после каждой успешной навигации на сайт браузер спрашивает `document.contentType`, и если это JSON, ставит дерево со сворачиванием (глубже 3 уровней и длиннее 500 элементов — свёрнуто), «Текст», «Текст с отступами», «Копировать»; до 20 МБ.
- Обновление при изменении файлов (`AutoReload` в `settings.ini`, переключатель на /net, решение пользователя 2026-09-29): `BrowserForm.WatchFolders` держит `FileSystemWatcher` (с подпапками) только на папках страниц на экране — `WorkDir` проекта (`Launcher.WorkDir`, владелец по `OwnerOf`) или папка открытого файла; пересчёт в `ShowState`, при сворачивании и смене переключателя. Шум (`Noise`: node_modules, .git, bin, obj…, логи, временные файлы) не считается; через 0,4 с тишины вкладки этой папки на экране делают `Reload`.
- «Для разработчика» (`Dev.cs`, `dev.html` на `https://start.litebro/dev`, задача пользователя 2026-09-29): переключатели кнопок и инструментов, выключенное — в `Disabled` в `settings.ini` (поле `DevOff`, id из `Dev.Ids` через пробел, чужие отбрасываются; нет строки — `Dev.DefaultOff`: инструменты разработчика после установки и сброса выключены, решение пользователя 2026-09-29; пустая строка — всё включено). «Настройки по умолчанию» там же (`App.ResetSettings`: `settings.ini` как после установки, старый — `.bak`, применяется сразу; движок перезапускается, только если меняются его флаги — `EngineKey` включает GPU и `ExtraBrowserArgs`). Кнопки панели (назад, вперёд, обновить, домик, звёздочка, память) пропадают одни, их клавиши работают; инструменты (сброс сайта, страна поиска, эмуляция, снимок, хранилище, JSON, заглушки, «Открыть рядом») — вместе с меню и клавишами (`Shortcut` с `when Dev.On(...)`: выключенная клавиша уходит движку); кнопки стартовой страницы (терминал, «только localhost», журнал, `>_` на плитках) — через `off` в сообщении `net`. Гаечный ключ пропадает, когда выключены эмуляция, снимок и хранилище; включённая эмуляция снимается (`ApplyDev`). Саму страницу выключить нельзя (решение пользователя): её кнопки — у правого края стартовой страницы (`#dev`, не в списке) и на /net. Новую кнопку или инструмент добавлять в `Dev.Ids` и `GROUPS` в `dev.html`.
- Сброс сайта (`BrowserForm.ResetSite`, Ctrl+Shift+R и Ctrl+F5, кнопка с ластиком справа от «Обновить», только на http/https): через DevTools-протокол `Storage.clearDataForOrigin` (`service_workers,cache_storage`) для источника страницы, `Network.clearBrowserCache` (HTTP-кэш всего профиля, по сайтам его не очистить) и `Page.reload` с `ignoreCache`. Cookies и хранилище не трогаются. В терминале эти клавиши уходят оболочке.
- Профиль проекта (`Project.OwnProfile` → `Project.Profile` = `project-<id>`, `Tab.Profile`, `App.CreateControllerAsync` с `ProfileName`): отдельные cookies, хранилище и разрешения в том же движке. Вкладка переезжает в профиль (контроллер пересоздаётся, история теряется) при `OpenProject` и при переходе на сайт проекта (`NavigationStarting`, владелец — `OwnerOf(tab, url)`: плитка, из которой открыта вкладка, иначе первая по сайту); чужие сайты (вход через OAuth) остаются в текущем профиле; всплывающие окна — в профиле открывшей вкладки. Смена галочки = заново входить на сайт проекта.
- Очистка при выходе (`ClearOnExit` в `settings.ini`, переключатель на /net): когда закрывается последнее окно, `OnFormClosing` прячет его и до 8 с чистит (`App.ClearDataAsync`) cookies и HTTP-кэш каждого профиля, открытого за сессию (скрытый контроллер в нём, `ClearBrowsingDataAsync`). `Project.KeepData` (по умолчанию включён, и у старых плиток тоже): свой профиль не трогается целиком, в общем остаются cookies его хостов (порты cookies не различают: остаются все cookies localhost). localStorage/IndexedDB не удаляются.
- Панель инструментов (`bar`, TableLayoutPanel): у каждого элемента своя ячейка (`SetCellPosition`), иначе скрытая кнопка сдвигает остальные и адресная строка попадает в узкую колонку. Кнопки одного квадратного размера по самой большой (`EvenButtons`, заново при смене DPI). «Назад»/«Вперёд» не выключаются (выключенные рисуются тёмными, решение пользователя). Работают через `BrowserForm.Step`: история движка читается DevTools-протоколом (`Page.getNavigationHistory`), свои страницы (`data:` — запуск, ошибка) и адрес, за который они стоят, пропускаются; история пропавших контроллеров (смена профиля, выгрузка) живёт в `Tab.Before`/`Ahead`, записи движка ниже `Tab.Floor` уже перенесены туда; вкладке без истории «Назад» открывает плитки.
- Полоса вкладок скрыта, пока в окне одна вкладка и это сама стартовая страница с плитками (`Home.IsTiles`, путь `/`; журнал, консоль и терминал — обычные вкладки) (`ShowStrip`, решение пользователя 2026-09-28); появляется с первым сайтом, плиткой или второй вкладкой (Ctrl+T). Закрытие последней вкладки (Ctrl+W, крестик, средний клик, `window.close()`) не закрывает окно, а заменяет её свежей стартовой страницей (`ReplaceWithHome`, общий профиль, без истории); окно закрывает только закрытие самой стартовой страницы или крестик окна (решение пользователя).
- Тема (`Theme.cs`): `Theme` в `settings.ini` — `auto` (как «Режим приложения» в Windows, переключается на лету через `SystemEvents.UserPreferenceChanged`), `dark`, `light`. Белую вспышку убирают переменная `WEBVIEW2_DEFAULT_BACKGROUND_COLOR` до создания окружения и `DefaultBackgroundColor` контроллера; страницы следуют через `Profile.PreferredColorScheme`. Заголовок — `DWMWA_USE_IMMERSIVE_DARK_MODE` (20, на старых Windows 10 — 19), адресная строка — недокументированная тема `DarkMode_CFD`.
- Отвергнуто ради памяти: `--in-process-gpu` (без песочницы GPU), `--disable-gpu`, V8 lite mode (тратят CPU).
- dsh (DeepSeek harness) запускать только с `--no-open`, иначе он сам открывает Chrome.
